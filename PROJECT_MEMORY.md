# Project Memory — Read This First

- Clean-slate STM32C011 add-on fridge defrost controller. Do not import code, constants, algorithms, or assumptions from other projects.
- Detailed source of truth: `defrost_controller_plan.md`; maintain it as decisions are made.
- Current phase: requirements/safety planning. No production algorithm or constants are approved.
- CubeIDE ownership rule: configure generated hardware through `DEFROST_controller.ioc`; add code only in Cube `USER CODE` regions or separate project-owned `Core/Src` and `Core/Inc` modules. Do not edit tool-managed/generated regions unless explicitly authorized. The initial clock conversion was explicitly authorized and synchronized in `.ioc` and generated clock code.
- Parameter ownership: all rebuild-time defrost algorithm/safety parameters live in the project-owned `Core/Inc/defrost_config.h`, never scattered through source or placed in generated regions. Every parameter comment states unit, purpose, increase/decrease effect, and relevant constraints; the header includes compile-time relationship checks. Pins/peripherals stay in the `.ioc`.
- Relay language: **energized = compressor power interrupted/defrost**; **de-energized = compressor power available/normal refrigerator control**.
- Goal: infer local ice and local melt completion from physically ordered temporal events in temperature/capacitance without customer commissioning or installation-specific raw capacitance thresholds, then melt it by temporarily inhibiting the compressor. Online learning may adapt to the current operating context, but a single permanently conditioned site profile is not sufficient. There is no heater.
- Sensor: PA4 USART2 half-duplex at 9600 baud. PA6 power-enable triggers streaming about 50 ms after power-up. Frame: `AA | big-endian int16 temperature | big-endian uint16 pF | big-endian CRC16 | AC`; CRC-16/CCITT-FALSE covers the four data bytes. Arm reception before power-on, accept the first valid streamed frame within 2000 ms, wait 10 ms, then power off. Initial timeout policy uses up to three attempts with 100 ms powered off between attempts; these retry values remain experimental.
- Logs: PA2 transmit-only software UART at 115200 baud; logging is lower priority than sensor and safety work.
- CSV log order: monotonic `ms`, sequence, sensor status, formatted signed Celsius (`raw / 100` with two decimals), capacitance pF, defrost-active flag, controller state, actual commanded relay state, event/reason, cold exposure, session/above-band/lockout timers, consecutive failures, acquisition/protocol diagnostics, and validated frame hex. Invalid records never repeat stale temperature/capacitance. Logs are never control inputs or algorithm-training evidence.
- Clock: internal HSI48 divided by 4 for 12 MHz SYSCLK/HCLK/PCLK. PC14/PC15 crystal is fitted but not configured or used by firmware.
- Measurement firmware: schedule sensor acquisition every 2 seconds, skip missed slots after long failure retries, and log CSV data/errors/raw valid frames on PA2. Relay remains permanently de-energized; no ice algorithm or defrost action is enabled. The current blocking software UART is experimental and must be waveform-tested/replaced before automatic control.
- Initial defrost policy: guarded learned melt evidence plus hysteretic 2-to-4-degree band control. At/below 2 degrees, inhibit the compressor; at/above 4 degrees, de-energize the relay and permit the refrigerator thermostat to run the compressor. This controller cannot force cooling. Repeated 2-to-4-degree cycling is intentional inside one active defrost. Crossing 4 degrees is not success or abort. Melt success requires temperature at/above 2 degrees plus learned capacitance criteria. Abort immediately at the configurable emergency ceiling initially 6 degrees, or after configurable cumulative time above the upper band initially 10 minutes. Above-band time pauses below 4 degrees and resets only when the session ends. Maximum session duration is configurable, initially four hours, and always mandatory.
- Crossing 0 degrees Celsius at one sensor does not prove all ice elsewhere has melted. A local 4-degree reading does not prove cabinet/food temperatures are safe. Use distributed reference temperature loggers during tests; add another cabinet sensor if the product must guarantee the warmest location.
- Reset/power-loss preference: de-energize relay, abandon active defrost, and return control to the refrigerator. Do not auto-resume. Hardware timed ride-through is only a future option if testing proves it necessary.
- Firmware must actuate the real relay according to the approved state machine; a permanently forced-de-energized/shadow-only implementation is not acceptable. All fail-safe paths still de-energize it.
- Sensor faults during defrost abort it and de-energize the relay. All time, temperature, persistence, lockout, relay-chatter, and sensor-retry limits are named rebuild-time parameters.
- Acquisition-failure policy: sample every 2 seconds in monitoring and active defrost. Normal monitoring initially allows three complete power-up attempts with 100 ms powered off between attempts. Active defrost allows one 2000 ms attempt per cycle and at least 100 ms sensor-off between cycles. A failed cycle increments a counter, a valid frame resets it, and an initial configurable limit of 10 consecutive active-defrost failures aborts in approximately 20–21 seconds.
- Confounders include installation environment, day/night/season, physical door activity, hot/steaming food, load changes, water/condensation, sensor drift/movement, spatial ice, and resets. The door input is reserved for future implementation and is not read or used by the current algorithm; door events must be tolerated only through their sensor effects.
- Diagnostic-log boundary: UART logs are only for interface bring-up, decoding/fault diagnosis, and human visibility. Never use captured logs to select features, derive/tune parameters, identify patterns, train anything, or justify algorithm conclusions. Specify and version-freeze the deterministic algorithm before automatic-control testing. The controller may still use live self-referenced history as runtime state.
- Pattern strategy: use guarded, dual-timescale online adaptation. A trusted wet, low-ice reference may update only from qualified post-defrost recovery data, while a short-term context model follows current temperature, thermal direction, and operating conditions. Freeze learning during suspected ice, defrost, faults, door/hot-load-like disturbances, and unstable recovery; bound every update so ice cannot quickly become normal. Exact representation and equations remain unapproved. Never convert captured log values into fixed production values.
- Native refrigerator temperature is expected to be sawtooth-like because its thermostat cycles the compressor. "Normal operation" means credible recurring cooling and warming legs, not a fixed or flat temperature. "Recovery" is the transient after defrost or a disturbance while the temperature/capacitance behavior returns to credible thermostat cycling; recovery data is quarantined from trusted-reference updates until qualification rules pass.
- Bootstrap choice: conservative scheduled bootstrap. Store cold exposure as saturating `uint32_t` centi-degree-Celsius-seconds. Each valid on-schedule two-second sample adds `max(0, -temperature_centiC) * 2`; invalid/unobserved/quarantined time adds zero. Saturate at 1,800,000 (5 degrees Celsius-hours). The 24-hour fallback requires at least 360,000 (1 degree Celsius-hour). Ordinary warming does not subtract exposure. Reset exposure and elapsed time after every successful or aborted attempt. The unused door input has no effect. Values cannot come from diagnostic logs.
- Context comparison: store a trusted wet/low-ice reference, qualified defrost-cycle excursion, confidence, and age. Use the signed contextual residual; do not normalize by sensor-noise variation. Scale the next trigger against an initial configurable fraction of 0.75 (3/4) of the previous qualified moderate-ice-to-after-melt excursion, using cross-multiplication rather than division. This is an operational trigger fraction, not an ice-coverage percentage. The wet-to-initial-freeze swing is optional event evidence only, not a required denominator. Never decide ice from raw capacitance or a low-confidence model.
- Reference protection: new after-melt wet values and defrost excursions remain candidates until local melt success, recovery quarantine, credible thermostat cycles, integrity/context checks, and bounded-update rules all qualify them. Aborted or uncertain defrosts never update the trusted model. The first bootstrap candidate has limited confidence and scheduled fallback remains authoritative until later confirmation.
- Initial melt detector: `C_start` is the median of five valid pre-defrost samples. Use 10-second median blocks; a 1-minute/six-block window is upward when net rise is positive and positive movement is at least 75% of absolute movement, for three consecutive evaluations. Then require 5-minute stabilization with range no greater than 25% of transition rise, final median above `C_start`, and at least 75% of peak rise retained. A reversal greater than 25% cancels only the candidate. Preserve session state across band cycling. Bootstrap success additionally requires current temperature at least 2 degrees Celsius and creates one PROVISIONAL event.
- Melt-model promotion: zero events = NO_MODEL; one qualified event = PROVISIONAL; two mutually consistent events = CONFIRMED; three mutually consistent events = TRUSTED. Provisional only checks/diagnoses consistency; confirmed may support but not replace physical qualification; trusted may qualify the capacitance side, while the 2-degree gate and all safety/fallback rules remain mandatory. Aborts create no event and inconsistent candidates are never averaged into the model.
- Sensor physical response (user-supplied design fact, not log-derived): at comparable conditions the material-state endpoints are **dry < ice < liquid water**, but the installed sensor is expected never to be dry. Within the relevant wet/ice operating range, wetting raises capacitance; freezing and accumulating ice lower it; thick full coverage produces the lowest contextual reading and an apparent lower plateau; melting raises capacitance again. Normal control must trigger from the earlier persistent downward contextual deviation/trend, not wait for the full-coverage plateau. Capacitance must not estimate numerical ice thickness. Temperature-only capacitance dependence, thermal lag, and sensor noise are negligible for algorithm design; temperature accuracy is high. Contamination or a persistent water film can permanently shift the baseline. Still unresolved: valid range, saturation, and sentinel values.
- Use a hybrid trigger: qualified contextual downward trend/phase confidence should trigger before full coverage, while conservative cold-exposure scheduling remains an independent fallback. A detected full-coverage plateau is an overdue backstop, not the target. Elapsed time alone still cannot trigger without credible frost-forming exposure.
- "Trusted reference" means a qualified wet, low-ice post-defrost context, never a dry reference; persistent film/contamination offsets may be learned only through the guarded recovery process. "Lowest means thick ice" is contextual, not a universal raw threshold.
- Scope/deferments: door input is future/unused; relay and mains hardware review is outside the current firmware scope; sensor numerical range/sentinel characterization may be completed later. Firmware still requires CRC/timeout/stale-data handling and fail-safe relay output behavior.
- Defrost-session spacing: after a successfully completed defrost, wait a configurable minimum of 4 hours before a new defrost may begin. This timer is not used inside an active defrost and therefore does not restrict repeated 2-to-4-degree cycling. An unsuccessful attempt separately enters an initial configurable 4-hour failed-attempt lockout.
- Relay dwell: no additional minimum relay-energized dwell or general relay-state dwell. The 2-to-4-degree hysteresis provides normal anti-chatter behavior. Melt success, the upper-band transition, and every safety/fault abort act immediately and cannot be delayed by a dwell timer.
- Failed defrost: immediately de-energize relay, reject session candidates, clear session-local melt state, and enter an initial configurable 4-hour failed-attempt lockout. Restore valid communication after a sensor abort. At lockout expiry do not execute the old ice request; require newly qualified evidence or renewed fallback eligibility.
- Event priority: emergency ceiling; sensor/fault abort; maximum session duration; cumulative time-above-band abort; melt success; band transition; new defrost trigger.
- Initial ice trend: one-minute aggregates, 5-minute short context, 60-minute long context, 15-minute downward persistence, 5-minute persistence at the trusted 0.75 excursion level, and 2-hour memory of qualified downward trend. Only TRUSTED can independently trigger; earlier trust levels use scheduling.
- Disturbance policy: normal monitoring only; freeze ice confidence/reference learning and pause but preserve exposure, keep the 24-hour timer running, then require two credible thermostat cycles. A persistent offset invalidates the contextual reference. Disable this detector during defrost and use the defrost-specific pattern.
- Important unresolved items: learned normal-cycle envelope bounds, learned event consistency/bounded commit equations, validation of experimental parameters, and justified EEPROM persistence.
